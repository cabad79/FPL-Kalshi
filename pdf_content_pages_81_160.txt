Features as Building Blocks
Machine learning models cannot read charts or interpret match reports. They require
inputs in a very specific shape: a table of numbers. Each row represents one observa‐
tion, such as a team in a given match or a player across a season. Each column
represents one feature, such as pass accuracy, possession share, or xG per shot.
Optionally, one column acts as the target—the outcome we want to predict, such as
whether a team won or lost.
Conveniently, the DataFrames we built during EDA already have this structure. A
team-level summary table has rows for teams and columns for statistics, and can
easily be extended with a target column. The same applies at the player or match
level. This is why EDA matters so much: it not only helps us understand the game,
but it also prepares the raw material for modeling.
In practice, much of the art of applied machine learning lies in deciding which
features to include. A model trained only on possession share and shots per game
may tell a different story from one trained on expected goals and defensive duels.
Choosing features is as much about understanding soccer as it is about manipulating
data. Analysts who know both the game and the data are best placed to make these
decisions.
The Standard Pipeline
By reframing descriptive statistics as features, we arrive at the standard pipeline used
across data science:
EDA → Features → Models
First, we explore data to see what is there. Next, we translate those insights into
structured features. Finally, we feed those features into models that generalize from
past matches to future ones. Each step is built on the preceding one, and each step
adds a layer of value. The skills you have practiced in this chapter (cleaning data,
building summaries, and drawing visualizations) are not just preliminary exercises.
They are the essential preparation for predictive modeling.

From Lines on a Field to Lines of Best Fit:
Linear Regression
Let’s start with the most fundamental regression algorithm: linear regression. The
concept is fairly intuitive; it’s all about finding a straight-line relationship between
one or more input variables (we’ll call them features or predictors) and a single output
variable (the target).
Imagine you’re a scout trying to estimate a young player’s future market value. You’d
probably look at a few key details: their age, the number of goals they’ve scored,
maybe the number of assists they’ve provided. Your brain intuitively creates a model:
a younger player with lots of goals is probably worth more. Linear regression does the
same thing, but with mathematical precision.
The algorithm tries to find the best straight line that describes the data. For example,
if we plot a player’s market value against the number of goals they scored last season,
we might see a pattern. As goals increase, market value tends to increase. Linear
regression finds the one line that cuts through that data and best represents that
trend.

Counting Goals: Poisson Regression
Linear regression is great for predicting continuous values like market value, but what
about counting things? In soccer, one of the most fundamental counts is the number
of goals scored in a match. This is a classic soccer analytics problem, and it has a
specific tool that is perfect for the job: Poisson regression.
Why can’t we just use linear regression to predict goals? There are a few reasons:
• Goals are counts, not continuous values. A team can score 0, 1, 2, or 3 goals, but
•
not 2.5 goals. Linear regression can predict fractional values, which don’t make
sense here.
• Goals are non-negative. A team can’t score negative goals. A linear regression
•
model could, in theory, predict a negative number.
• The relationship isn’t always linear. The factors that influence goal scoring might
•
not have a simple straight-line relationship with the number of goals.
Poisson regression is a type of generalized linear model (GLM) that is specifically
designed for count data. This model makes a few key assumptions, most notably that
the number of events (goals) in a fixed interval (a match) is, on average, constant, and
the events are independent. This fits the scenario of a soccer match quite well.

Finding Similar Players: K-Nearest Neighbors Regression
So far, we’ve looked at models that try to find a mathematical formula (a line or
a curve) to describe the relationship between features and a target. But what if the
relationship is too complex for a simple formula? What if we just want to find players
who are similar to a given player and see their market values?
This is where KNN regression comes in. It’s a completely different way of thinking
about prediction. Instead of learning a single model from all the data, KNN makes
predictions on the fly by looking at the neighbors of a data point.
The idea is simple and intuitive:
1. Choose a number k. This is the number of neighbors to consider.
1.
2. Find the k nearest neighbors by finding the k players in your dataset who are
2.
most similar, based on their features (e.g., goals, assists, age), to the new player
you want to predict the value for.
3. Average their values. The predicted market value for the new player is simply the
3.
average market value of their k nearest neighbors.
It’s like asking, “This new young striker scored 15 goals last season. Who are the five
most similar players to them in my database, and what are their market values?” The
average of those values is your KNN prediction.

obscure local patterns. Finding the optimal k often involves trying several values and
seeing which one gives the best performance on a validation set—a topic we’ll explore
more in the following section.

in Soccer Contexts
Building a model is one thing, but knowing whether it’s any good is another. In
the world of soccer analytics, a model that can’t be trusted is worse than no model

Using Key Performance Metrics
We’ve already touched on R2, but let’s formalize it and introduce a few other key
metrics:
R-squared (R2)
As you saw, this tells you the proportion of the variance in the target variable that
is predictable from the feature(s). It’s a measure of how well the model explains
the data. A higher R2 is generally better, but it’s not the whole story. A high R2
on your training data doesn’t guarantee that the model will perform well on new,
unseen data.

Mean absolute error (MAE)
This is the average of the absolute differences between the predicted and actual
values. It gives you a straightforward idea of how wrong your predictions are on
average, in the original units of the target variable. For our market value model,
an MAE of 5 would mean our predictions are off by €5 million on average.
Mean squared error (MSE)
This is the average of the squared differences between the predicted and actual
values. By squaring the errors, larger errors are penalized more heavily than
smaller ones. The metric is common, but because the units are squared (e.g.,
millions of euros squared), it can be hard to interpret.
Root mean squared error (RMSE)
This is the square root of the MSE. It brings the metric back to the original units
of the target variable, making it easier to interpret than MSE. It’s like MAE, but it
still gives more weight to larger errors.

Training set
The largest part of the data, used to train the model.
Validation set
Used to tune the model’s parameters (like the k in KNN) and to compare models.

Advanced Topics in Poisson Regression:
Overdispersion and Zero-Inflation
While Poisson regression is a powerful tool for modeling count data, it makes a
strong assumption: that the mean and variance of the data are equal. In the real world
of soccer analytics, this assumption often doesn’t hold. Let’s explore two common
issues and how to address them.
Overdispersion: When Variance Exceeds the Mean
In many soccer datasets, you’ll find that the variance in goals scored is greater than
the mean. This is called overdispersion. For example, if the average number of goals
per match is 1.5, but some matches have 0 goals while others have 5 or 6, the variance
will be much larger than 1.5.
Advanced Topics in Poisson Regression: Overdispersion and Zero-Inflation 
| 
103


================================================================================
PAGE 124
================================================================================
Why does this matter? When overdispersion is present, the standard errors of the
Poisson model are underestimated, which means your confidence intervals will be
too narrow and your p-values will be too optimistic. A p-value tells you how statisti‐
cally significant your result is. Typically, a p-value below 0.05 is deemed statistically
significant, and above this threshold is considered insignificant, though this cutoff
can vary with the use case. You might think a predictor is significant when it’s not.
To check for overdispersion, we can calculate the dispersion parameter (φ; phi):
# Using our previous Poisson model
residuals = model.resid_pearson  
phi = sum(residuals ** 2) / (
    len(goals_df) - len(model.params)
)  
print(f"Dispersion parameter: {phi:.2f}")
Pearson residuals are standardized residuals that should have a variance close to 1
if the model fits well.
The dispersion parameter is calculated by dividing the sum of squared Pearson
residuals by the degrees of freedom.
If φ is much greater than 1 (say, greater than 1.5), you have overdispersion. In such
cases, a negative binomial regression model is often more appropriate.
Negative Binomial Regression
The negative binomial model is a generalization of the Poisson model that allows
the variance to be greater than the mean. It introduces an additional parameter that
captures the extra variability in the data:
import statsmodels.formula.api as smf
# Fit a negative binomial model
nb_model = smf.negativebinomial(
    "Goals ~ ShotsOnTarget", data=goals_df,
).fit()
print(nb_model.summary())
The negative binomial model will typically provide more-realistic standard errors
and confidence intervals when overdispersion is present. It’s a go-to model for soccer
goal data.

Another common issue in soccer data is zero inflation—an excess of matches with no
goals. This can happen for various reasons: strong defensive tactics, poor attacking
play, or even weather conditions. Standard Poisson or negative binomial models
might not capture this pattern well.

Model Diagnostics: Ensuring That Your Model Is Sound
Building a model is one thing; ensuring it’s reliable is another. Model diagnostics are
the checks and balances that help you understand whether your model is trustworthy.
In this section, we’ll cover some essential diagnostic techniques for regression models
in soccer analytics.
Residual Analysis: Looking for Patterns
You’ve already seen residual plots for linear regression. The same principle applies
to GLMs. Residuals are the differences between what your model predicts and what
actually happened. A good model should have residuals that are randomly scattered,
with no clear patterns.
GLMs can have several types of residuals:
Pearson residuals
Standardized residuals that should have a mean of 0 and a variance of 1 if the
model fits well.
Deviance residuals
Measure each observation’s contribution to the model’s deviance (a measure of
model fit).

Goodness-of-Fit Tests
How do we quantify how well our model fits the data? Several tests can help:
Deviance test
Compares the model’s deviance to a chi-squared distribution. A low p-value
suggests poor fit.
Pearson chi-square test
Similar to the deviance test but uses Pearson residuals.
Here’s how to conduct goodness-of-fit tests:
# Calculate deviance

# Compare to chi-squared distribution

p_value = 1 - chi2.cdf(deviance, df_resid)
print(f"Deviance: {deviance:.2f}")
print(f"Degrees of Freedom: {df_resid}")
print(f"P-value: {p_value:.4f}")
If the p-value is very low (e.g., < 0.05), it suggests the model doesn’t fit the data
well. This could be due to overdispersion, missing predictors, or an incorrect model
specification.

Common Pitfalls and Practical Tips
As you build regression models for soccer analytics, you’ll encounter challenges. Here
are common pitfalls to avoid, as well as some practical tips, learned from real-world
experience.
Pitfall 1: Overfitting to the Training Data
The problem: Your model performs brilliantly on the training data (R2 = 0.99!) but
terribly on new data. This is overfitting; the model has memorized the training data
instead of learning general patterns.
The solution: Always use a separate test set, or cross-validation. If your training per‐
formance is much better than your test performance, you’re overfitting. Simplify your
model by removing features, using regularization, or collecting more data. Here’s how
to implement a cross-validation test:
from sklearn.model_selection import cross_val_score
from sklearn.linear_model import PoissonRegressor
# Use scikit-learn's Poisson regressor for cross-validation
X = match_data[["ShotsOnTarget", "Possession", "HomeAdvantage"]]
y = match_data["Goals"]
model_sk = PoissonRegressor()
cv_scores = cross_val_score(
    model_sk, X, y, cv=5, scoring="neg_mean_absolute_error"
)  
print(
    "Cross-validation MAE: "
    f"{-cv_scores.mean():.2f} "
    f"(+/- {cv_scores.std():.2f})"
)
We use five-fold cross-validation. The model is trained on four folds and tested
on the fifth, repeated five times.
For our dataset, the cross-validation MAE is 0.94 (+/– 0.15), providing a more robust
estimate of out-of-sample performance.
Pitfall 2: Ignoring Multicollinearity
The problem: Two or more of your features are highly correlated with each other
(e.g., shots and shots on target). This makes it hard to interpret coefficients and can
make the model unstable.
The solution: Check for multicollinearity by using the variance inflation factor
(VIF). Remove or combine highly correlated features. Here’s how to check for
multicollinearity:

Time Series and Sequential Data
Soccer is inherently temporal. A season unfolds over months, a match over 90
minutes, and a play over seconds. The models we’ve built in this chapter treat each
observation as independent, but in reality, what happens in one match affects the
next.
Time-series models explicitly account for this temporal structure. They can capture
trends (is a team improving over the season?), seasonality (do teams perform better
at home in winter?), and autocorrelation (does a win in one match make a win in the
next more likely?).
Advanced time-series techniques like autoregressive integrated moving average
(ARIMA), state-space models, and recurrent neural networks can model these
dynamics. They’re essential for forecasting player performance, predicting league
standings, and understanding momentum.
That being said, such techniques require more sophistication and go beyond the
scope of this book. You will see that you can accomplish a lot already with regression
and classification techniques, as well as deep learning.
Causal Inference: Beyond Prediction
Regression models are great for prediction, but they’re not designed for causal
inference. Just because shots on target are correlated with goals doesn’t mean that
increasing shots on target will cause more goals. Confounding variables (e.g., team
quality) could affect both.
Causal inference techniques like randomized controlled trials, instrumental variables,
and difference-in-differences can help you answer what if questions. What if we
changed our formation? What if we signed this player? What if we implemented this
training program?
These techniques are more complex and require stronger assumptions, but they’re
essential for making strategic decisions. In the coming chapters, we’ll explore some of
these methods and how they apply to soccer.

its size, the texture of its panels. You are taking in features (weight, size, texture) to
assign a class (size 4 or size 5). That’s classification.
In soccer analytics, the principles are the same, but the stakes are higher and the data
is more complex. We replace soccer balls with game events, and our intuition with
powerful algorithms.

(like 90%), the log odds are a positive number (like +2.2), reflecting that team’s
advantage. If a team is the massive underdog (like 10%), the log odds are a negative
number (like –2.2), mathematically capturing the unlikelihood of a win.

Precision and Recall: The Two Sides of Performance
From the confusion matrix, we can derive two crucial metrics:
Precision
Of all the times the model predicted Goal, what percentage were goals? This
metric measures the quality of the positive predictions.
precision = TP / (TP + FP)
Recall (or sensitivity)
Of all the goals that happened, what percentage did the model correctly identify?
This measures the model’s ability to find all the positive instances.
recall = TP / (TP + FN)
In soccer analytics, a trade-off often occurs between these two metrics, and which one
you prioritize depends on your use case.
Imagine you’re using the model to decide which shots to highlight in a post-match
analysis video. If you want high precision, you’ll include only shots the model is very
confident about. You won’t waste time on false alarms, but you might miss some
surprising goals. This is a cautious approach: better safe than sorry.
Now imagine you’re a defensive coach trying to identify all dangerous situations your
team faced. Here, you want high recall. You’d rather review a few extra clips (false
positives) than miss a single dangerous chance (false negative). This is an aggressive
approach: better to be thorough.
The key insight is that there’s no single best model. The right balance depends on the
cost of different types of errors in your specific context. A good analyst understands
this trade-off and tunes the model accordingly.

Evaluation of Probabilistic Models with Cost Functions
While the ROC curve helps us understand how well a model ranks probabilities, it
does not tell us whether the probabilities themselves are accurate. Up to this point,
we have largely relied on accuracy—the percentage of correct predictions. While
accuracy is intuitive, it is often the wrong metric for soccer analytics, particularly
when dealing with rare events like goals.
If a model predicts that every single shot will not result in a goal, that model will
be right about 90% of the time, achieving 90% accuracy. Yet, this model is entirely
useless for evaluating finishing skill or chance quality. In soccer, we rarely want

a simple yes-or-no prediction. Instead, we want a probability: what is the exact
likelihood that this specific shot, from this angle, under this pressure, will result in a
goal?
To evaluate how well a model estimates these probabilities, we use cost functions
(also known as loss functions or evaluation metrics). A cost function measures the dif‐
ference between the predicted probability and the actual outcome. The model’s goal
during training is to minimize this cost. Two of the most important cost functions for
probabilistic classification in soccer are log loss and the Brier score.
Log loss (cross-entropy loss)
Log loss heavily penalizes models for being both confident and wrong. If a model
predicts a 99% chance of a goal, and the shot misses, the log loss will be extremely
high. Conversely, if it predicts a 10% chance of a goal and the shot misses, the penalty
is small.
Log loss is the default cost function for many advanced algorithms, including logistic
regression and the tree-based models we will build in the next chapter. Log loss
forces the model to output well-calibrated probabilities rather than just pushing
predictions toward 0 or 1. When you see eval_metric="logloss" in code, the model
is being instructed to minimize this exact penalty. (You will also see this referred to as
cross-entropy loss when we reach deep learning in Chapter 7).
Brier score
The Brier score is another common metric for probabilistic forecasts. It is simply the
mean squared difference between the predicted probability (from 0 to 1) and the
actual outcome (1 for an event happening, 0 for it not happening).
A Brier score of 0 indicates perfect predictions, while a score of 1 indicates perfectly
wrong predictions. Unlike log loss, which can grow infinitely large if a model is
completely confident and wrong, the Brier score is bounded between 0 and 1. This
makes it somewhat easier to interpret and compare across datasets.
Calibration
Both log loss and Brier score reward models for good calibration. A model is well
calibrated if its predicted probabilities match the real-world frequencies. If an xG
model assigns a 0.3 probability to 100 different shots, we expect exactly 30 of those
shots to result in goals. If only 10 go in, the model is poorly calibrated, even if it
correctly identified them as low-probability chances.
When building models for xG, expected threat (xT), or pass completion probability,
minimizing log loss or Brier score ensures that the outputs are true probabilities that
coaches and analysts can trust, rather than just abstract scores.
